# tgdlbot — Telegram Video Downloader Bot

Telegram-бот для скачивания отдельных видео с YouTube (включая Shorts) и Instagram.
Бот выбирает качество, скачивает видео через yt-dlp и отправляет его в чат.
Файлы больше 50 МБ разбиваются на части; временные файлы удаляются после завершения,
ошибки или отмены задания. Для видео формируется обложка и определяются размеры кадра.

## Быстрый старт с Docker

Нужны Git, Docker с Compose v2 и токен от [@BotFather](https://t.me/BotFather).
Python, uv, Deno и FFmpeg на хосте для этого способа не требуются.
Готовые образы поддерживают `linux/amd64` и `linux/arm64`, в том числе Raspberry Pi
с 64-битной ОС (`uname -m` → `aarch64`).

1. Клонируйте репозиторий и создайте файл настроек:

   ```bash
   git clone https://github.com/amerbaev/tgdlbot.git
   cd tgdlbot
   cp .env.example .env
   ```

2. Создайте бота командой `/newbot` у @BotFather и запишите его токен в `.env`:

   ```dotenv
   TELEGRAM_BOT_TOKEN=ваш_токен_здесь
   ```

3. Подготовьте каталоги и запустите бота:

   ```bash
   mkdir -p downloads cookies
   docker compose up -d tgdlbot
   docker compose logs -f tgdlbot
   ```

   Compose скачает `ghcr.io/amerbaev/tgdlbot:latest` для архитектуры хоста.
   Контейнер работает от `appuser` с UID 1000: каталог `downloads/` должен быть
   доступен ему для записи, а файлы cookies — для чтения. Если каталог создан
   другим пользователем, настройте его владельца или права перед запуском.
   Для приватного пакета сначала выполните [вход в GHCR](#образы-и-ci).

Остановка:

```bash
docker compose down
```

Бот получает сообщения через polling. Публиковать порты контейнера и настраивать
webhook не требуется; нужен исходящий доступ к Telegram и сайтам с видео.

## Использование

| Команда или действие | Результат |
| --- | --- |
| `/start` | Приветствие и основные ограничения |
| `/help` | Справка по ссылкам и работе в группах |
| `/download ссылка` | Скачать одно видео |
| Ссылка отдельным сообщением в личном чате | Скачать одно видео |
| Кнопка «Отмена» под сообщением о скачивании | Запросить отмену своего задания |

В группе используйте `/download ссылка`, отдельное упоминание `@имя_бота ссылка`
или ответ на сообщение бота, содержащий только ссылку. Остальные обычные сообщения
бот игнорирует. Если в группе несколько ботов, команду можно адресовать явно:
`/download@имя_бота ссылка`.

Отправляйте одну ссылку за раз, без поясняющего текста:

- YouTube: `https://www.youtube.com/watch?v=...` или `https://youtu.be/...`.
- Shorts: `https://www.youtube.com/shorts/...` и `https://m.youtube.com/shorts/...`.
- Instagram: `https://www.instagram.com/p/...` и `https://www.instagram.com/reel/...`.

Параметры ссылок, например `?si=...` и `?feature=share`, поддерживаются.
Плейлисты, публикации с несколькими видео и прямые трансляции не обрабатываются.
Доступность конкретного ролика зависит от ограничений платформы.

## Настройки

Пример — в [`.env.example`](.env.example). Для локального запуска `.env` читает
`python-dotenv`; в Docker переменные передаёт Compose. Не публикуйте токен и cookies:
`.env` и каталог `cookies/` исключены из Git и контекста Docker-сборки.

| Переменная | Назначение | Значение по умолчанию |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | Обязательный токен Telegram-бота | Нет; без него бот не запускается |
| `INSTAGRAM_COOKIES_FILE` | Необязательный путь к файлу cookies Instagram в формате Netscape | Пусто: без сессии |
| `TGDLBOT_IMAGE_TAG` | Тег production-образа в Compose | `latest` |
| `TGDLBOT_TEST_IMAGE_TAG` | Тег test-образа в Compose | `test` |

Две переменные с тегами относятся только к Compose. Лимиты размера, число заданий
и каталог загрузок задаются константами в [`config.py`](config.py), а таймауты
обработки видео — в [`media.py`](media.py); через `.env` они не меняются.

После изменения переменных окружения пересоздайте контейнер:

```bash
docker compose up -d --force-recreate tgdlbot
```

`docker compose restart` не применяет новые переменные и не обновляет образ.

## Качество и ограничения

Размеры ниже соответствуют единицам в коде: 1 МБ = 1024 × 1024 байта.

- Не более трёх активных заданий на экземпляр бота и одного на пользователя.
  При занятости запрос отклоняется с предложением повторить его позже;
  ожидающие задания не сохраняются в очередь.
- Исходный скачанный файл — до 500 МБ. Файл или каждая часть для отправки — до 50 МБ.
- **YouTube:** приоритет 1080p → 720p → 480p → 360p. Варианты 1080p и 720p
  пропускаются, если размер неизвестен или оценка превышает 75 МБ.
  Для отдельных потоков учитываются видео и аудио. Это оценка, поэтому выбранный
  вариант может потребовать нарезки. Для вертикальных Shorts качество определяется
  по короткой стороне: 1080×1920 соответствует 1080p.
- **Instagram:** выбирается лучший доступный MP4, с переходом к лучшему доступному
  формату, если MP4 нет.
- Файлы до 50 МБ отправляются целиком. Для больших файлов начальная длительность
  частей рассчитывается с ориентиром на 45 МБ, затем размер проверяется по факту.
  Число и размеры частей заранее не гарантируются.
- Нарезка перекодирует видео в H.264 (`libx264`, CRF 18, preset `fast`) и звук в AAC.
  Она сохраняет временные метки кадров через `fps_mode=passthrough` и
  `enc_time_base=demux`. Перекодирование требует CPU и может немного изменить качество.
  Если часть слишком велика, её длительность сокращается с учётом фактического
  размера и запаса 20%; на часть предусмотрено две попытки.
- Таймаут `ffprobe` — 30 секунд, одной операции нарезки FFmpeg — 300 секунд,
  одной попытки создания превью — 15 секунд. Ошибка превью не блокирует отправку видео.
- Отмена проверяется между этапами скачивания и в progress hook yt-dlp.
  Она не прерывает уже выполняющуюся операцию FFmpeg или отправку в Telegram мгновенно.
  Очистка ждёт завершения фоновой работы.

## Локальный запуск

Нужны Python 3.14+, [uv](https://docs.astral.sh/uv/getting-started/installation/)
и `ffmpeg`/`ffprobe` в `PATH`. FFmpeg должен поддерживать `libx264`, AAC,
`fps_mode` и `enc_time_base=demux`. Его используют для объединения потоков,
нарезки, обложек и определения размеров видео.

После клонирования репозитория выполните из его корня:

```bash
cp .env.example .env
# Запишите TELEGRAM_BOT_TOKEN в .env перед запуском.
uv sync --locked --extra dev
uv run --locked python bot.py
```

`--locked` использует версии из [`uv.lock`](uv.lock) и сообщает об ошибке, если
lock-файл не соответствует `pyproject.toml`. Каталог `downloads/` создаётся при
первом скачивании; у запускающего пользователя должны быть права записи.

Deno устанавливается как зависимость `yt-dlp[curl-cffi,deno]`; `yt-dlp-ejs`
содержит скрипты для JavaScript-проверок YouTube. Оба компонента входят и в Docker-образ.
Используются стандартные клиенты yt-dlp. Без доступного runtime или совместимых EJS
часть форматов YouTube может отсутствовать. Подробнее —
[инструкция yt-dlp по EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS).

## Обновление и локальная сборка

Чтобы получить последний опубликованный образ из `master`, выполните:

```bash
docker compose up -d tgdlbot
# Или: make up
```

В Compose задано `pull_policy: always`: образ проверяется в GHCR, и контейнер
пересоздаётся, если образ изменился. Для запуска конкретной опубликованной ревизии
укажите `TGDLBOT_IMAGE_TAG=sha-<полный SHA>` в `.env` и повторите команду.
Для возврата к предыдущей ревизии укажите её SHA-тег.

Для разработки используется [`docker-compose.build.yml`](docker-compose.build.yml).
Он задаёт локальные теги и отключает скачивание готовых образов:

```bash
make build       # Собрать tgdlbot:production
make build-test  # Собрать tgdlbot:test
make up-local    # Собрать текущий код и запустить бота
make test-docker # Собрать текущий код и запустить тесты
```

`make up-local` требует тех же `.env` и каталогов, что и обычный Docker-запуск.
Без дополнения Compose использует GHCR, даже если перед этим выполнен `make build`.
Прямые команды сборки:

```bash
docker build --target production -t tgdlbot:production .
docker build --target test -t tgdlbot:test .
```

Dockerfile использует BuildKit и устанавливает зависимости по `uv.lock`.
Production содержит FFmpeg и работает от UID 1000. Test содержит dev-зависимости,
но не FFmpeg: проверки с настоящим FFmpeg выполняются отдельно в production-образе.

Остальные команды описаны в `make help`: `make logs`, `make down`, `make restart`,
`make shell`, `make install`, `make dev`, `make test`. `make clean` удаляет локальные
видеофайлы из `downloads/` и кеши Python/pytest; запускайте его после остановки бота.

## Тестирование

Тесты используют подмены внешних сервисов и временные каталоги, не обращаются
к живым Telegram/YouTube/Instagram и не удаляют рабочие загрузки. Токен не нужен.
После `uv sync --locked --extra dev`:

```bash
uv run --locked pytest tests/ -v
# Или: make test

# Отдельная проверка:
uv run --locked pytest tests/ -v -k test_name

# Текущий локальный код в Docker:
make test-docker

# Опубликованный test-образ из GHCR:
docker compose --profile test run --rm test
```

Тестовый контейнер запускается без сети и не получает `.env` с токеном.
`test_video_*_ffmpeg.py` проверяют нарезку, порядок кадров, обложки и размеры
с реальными `ffmpeg`/`ffprobe`; без этих программ проверки пропускаются.
В production-образе их можно выполнить без установки pytest:

```bash
make build
docker run --rm --network none -v "$PWD/tests:/app/tests:ro" tgdlbot:production \
  python -m unittest discover -s tests -p 'test_video_*_ffmpeg.py' -v
```

## Образы и CI

Workflow [Container images](https://github.com/amerbaev/tgdlbot/actions/workflows/images.yml)
запускается для PR в `master`, push в `master` и вручную через GitHub Actions.
Этапы — `build → test → publish`: по четыре сборки и проверки
(`production`/`test` × `amd64`/`arm64`) на нативных runners.

В тестах проверяются архитектура образа и запуск Python. Test-образ проходит
офлайн-набор pytest, production — проверки с реальным FFmpeg. Между jobs образы
передаются через artifacts, поэтому публикуются именно проверенные образы без
повторной сборки. Artifacts хранятся три дня; после их удаления нужен новый build.
Публикация выполняется после успешных проверок только для `master`, включая
ручной запуск этой ветки. PR образы не публикует.

| Образ в `ghcr.io/amerbaev/tgdlbot` | Обновляемые теги | Тег конкретного коммита |
| --- | --- | --- |
| Production | `latest`, `master` | `sha-<полный SHA>` |
| Test | `test` | `test-sha-<полный SHA>` |

Эти теги содержат `linux/amd64` и `linux/arm64`; Docker выбирает вариант хоста.
Для приватного пакета выполните `docker login ghcr.io` с personal access token
(classic), имеющим `read:packages`, по [инструкции GitHub](https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-container-registry).
Для публичного пакета авторизация не нужна.

CI использует встроенный `GITHUB_TOKEN`; право `packages: write` есть только
у job `publish`. Если пакет уже существует, репозиторию нужен доступ к нему
в настройках пакета **Manage Actions access**.

## Диагностика

### Instagram: `empty media response`

Ошибка возникает при получении данных о публикации, до скачивания файла.
Она может быть связана с требованием входа, ограничениями IP или изменениями
Instagram; сама по себе не означает, что видео слишком большое или удалено.
Поддержка браузерной имитации `curl-cffi` включена в зависимости yt-dlp.

Если актуальный образ не скачивает ролик, подключите сессию Instagram:

1. Войдите в Instagram в браузере и убедитесь, что ролик воспроизводится.
2. Экспортируйте cookies **только Instagram** в формате Netscape по
   [инструкции yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#how-do-i-pass-cookies-to-yt-dlp)
   и сохраните их в `cookies/instagram.txt` рядом с Compose-файлом.
3. В `.env` задайте путь внутри контейнера:

   ```dotenv
   INSTAGRAM_COOKIES_FILE=/app/cookies/instagram.txt
   ```

   Для локального запуска: `INSTAGRAM_COOKIES_FILE=cookies/instagram.txt`.
   UID 1000 должен иметь доступ к файлу и родительскому каталогу.
4. Примените настройку: `docker compose up -d --force-recreate tgdlbot`.

Сессия общая для всех пользователей бота: они смогут скачать по ссылке видео,
доступные этому Instagram-аккаунту, включая закрытые. Используйте отдельный аккаунт
без подписок на закрытые профили. Бот не проверяет личные права доступа пользователя.

Cookies применяются только к Instagram. Каталог подключается только для чтения;
каждая операция использует отдельную копию cookies в памяти и не меняет исходный
файл. При истечении сессии замените экспорт. Чтобы отключить её, очистите переменную
и пересоздайте контейнер. Cookies не гарантируют доступ к удалённым роликам или
обход ограничений платформы. Предупреждения yt-dlp доступны в логах.

### Разрывы соединения с Telegram

При временных сетевых ошибках бот автоматически повторяет подключение, в том числе
при запуске. Получение сообщений возобновляется после восстановления сети.
Обрывы записываются как `WARNING` без traceback; ошибки приложения сохраняют
traceback, а неверный токен останавливает запуск.

Прерванные команды и отправки видео автоматически не повторяются: после
восстановления связи отправьте запрос заново. При постоянных ошибках DNS проверьте
исходящий доступ к `api.telegram.org`.

### Docker: права и архитектура

- `Permission denied` в `downloads/`: проверьте права записи для UID 1000 на хосте.
- Cookies не читаются: проверьте путь внутри контейнера и права чтения для UID 1000.
- `exec format error` на Raspberry Pi: нужна 64-битная ОС и ARM64-образ.
  Не задавайте `platform: linux/amd64` или `DOCKER_DEFAULT_PLATFORM=linux/amd64`.
  Если закреплён старый тег без ARM64, смените его на доступный тег с обеими
  архитектурами, затем выполните:

  ```bash
  docker compose pull tgdlbot
  docker compose up -d --force-recreate tgdlbot
  ```

## Структура и разработка

| Путь | Назначение |
| --- | --- |
| [`bot.py`](bot.py) | Telegram-команды, допуск заданий, скачивание, отправка и отмена |
| [`config.py`](config.py) | Переменные окружения и лимиты |
| [`media.py`](media.py) | Нарезка, обложки, размеры кадра и очистка файлов |
| [`platforms/`](platforms/) | Проверка URL и выбор форматов YouTube/Instagram |
| [`tests/`](tests/) | Офлайн-тесты и проверки с FFmpeg |
| [`Dockerfile`](Dockerfile) | Отдельные production- и test-образы |
| [`docker-compose.yml`](docker-compose.yml) | Запуск готовых образов из GHCR |
| [`docker-compose.build.yml`](docker-compose.build.yml) | Дополнение для локальной сборки |
| [`Makefile`](Makefile) | Команды запуска, сборки, тестирования и очистки |
| [`pyproject.toml`](pyproject.toml), [`uv.lock`](uv.lock) | Зависимости и закреплённые версии |
| [`.github/workflows/images.yml`](.github/workflows/images.yml) | Сборка, проверка и публикация образов |

Telegram-обработчики асинхронные; блокирующие yt-dlp и FFmpeg выполняются через
`asyncio.to_thread()`. У задания есть UUID для имён файлов и очистки; при остановке
приложение ждёт фоновые задачи перед завершением работы.

Для новой платформы наследуйте [`BasePlatform`](platforms/base.py), реализуйте
`name`, `url_pattern` и `get_format_options(info)`, экспортируйте класс из
`platforms/__init__.py` и добавьте экземпляр в `PLATFORMS` в `bot.py`.
Проверки URL и выбор форматов покройте офлайн-тестами в `tests/platforms/`.

Зависимости добавляются через `uv add package_name`; фиксируйте изменения
`pyproject.toml` и `uv.lock` вместе. При обновлении yt-dlp согласуйте закреплённую
версию `yt-dlp-ejs` с его требованиями и запустите тесты.
