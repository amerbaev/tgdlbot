`pyproject.toml` повышает минимум yt-dlp; `tool.uv.constraint-dependencies`

применяет uv; для воспроизводимой установки следует использовать `uv sync --locked`.

с исходным lockfile подтвердило: других добавленных, удалённых или обновлённых
пакетов нет. Revision lockfile изменился с 3 на 5; resolver также нормализовал
маркер зависимости cffi → pycparser. Хеши артефактов получены resolver из PyPI,
вручную не редактировались.

[GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2)
подтверждён: затронут certifi <2026.10.18, рекомендуемое обновление — >=2026.10.19.

сертификаты: этого root нет ни в certifi нового образа, ни в системном SSL store.
Оставшиеся emSign roots сами по себе не означают наличие данной уязвимости:
2026.10.19 восстановил незатронутые сертификаты.

## Отдельный вывод о mediaconnect

`mediaconnect` **устарел и не поддерживается**. Его нет в `INNERTUBE_CLIENTS`
ни у исходного yt-dlp 2026.8.19, ни у 2026.10.26. Удаление подтверждено
[обсуждением разработчиков yt-dlp](https://github.com/yt-dlp/yt-dlp/issues/12596).
Это существующая проблема конфигурации проекта, а не регрессия данного обновления.

В `platforms/youtube.py` он остаётся принудительным клиентом для 1080p/720p;
`test_uses_mediaconnect` проверяет только эту настройку и не доказывает поддержку
клиента. Код yt-dlp пропускает неподдерживаемые клиенты с предупреждением,
после чего выбирает default. Дополнительно бот уже подавляет предупреждения
YouTube через `no_warnings=True`. Это поведение в данном обновлении не изменено.

В production нет Deno/Node и пакета yt-dlp-ejs. Живая проба показала предупреждение
об отсутствии JS runtime и выбор `visionos`; доступность полного набора форматов
не гарантирована. [Официальная инструкция EJS](https://github.com/yt-dlp/yt-dlp/wiki/EJS)
требует отдельный JS runtime и challenge solver.

Следующая отдельная правка: убрать устаревшее требование mediaconnect и устаревшие
утверждения в документации, проверить поддержку актуальных default-клиентов,
выбрать и закрепить EJS/runtime для Docker и добавить проверку границы с реальным
yt-dlp. Для Instagram отдельно проверить доступность конкретного ролика и сессию.
Эти изменения не смешаны с приоритетным обновлением зависимостей.

## Воспроизведение

С uv 0.13.6 и установленным Python 3.14:

```sh
uv sync --locked --extra dev --python 3.14
uv lock --check --offline
uv pip check
uv run --locked pytest tests/ -q
docker build --pull --target production -t tgdlbot:deps-2026-10-29-production .
docker build --target test -t tgdlbot:deps-2026-10-29-test .
docker run --rm --network none tgdlbot:deps-2026-10-29-test python -m pytest tests/ -q
```
